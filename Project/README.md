# Clicker AI — «ИИ от сбора до внедрения»

Бот для онлайн-кликера **Cookie Clicker** (https://orteil.dashnet.org/cookieclicker/)
на основе детектора YOLOv8. Модель находит на экране 4 класса объектов,
а `app.py` по ним управляет мышью.

| id | класс      | что это                                   | действие бота            |
|----|------------|-------------------------------------------|--------------------------|
| 0  | `game`     | большая печенька                          | кликать                  |
| 1  | `bonus`    | золотая печенька (бонус)                  | кликнуть сразу           |
| 2  | `upgrade`  | доступная покупка (здание / улучшение)    | купить                   |
| 3  | `close_ad` | крестик всплывающего окна («реклама»)     | закрыть                  |

## Структура проекта

```
clicker_ai/
├── screenshots/            # Задача 1: 36 исходных скриншотов
├── dataset/                # Задача 2: разметка YOLO HBB
│   ├── images/{train,val}  # 29 / 7 изображений
│   ├── labels/{train,val}
│   ├── classes.txt
│   └── data.yaml
├── train.py                # Задача 3: обучение -> runs/detect/clicker/weights/best.pt
├── app.py                  # Задача 4 + отчёт п.3-6: бот
├── collect.py              # Задача 5: автосбор скриншотов экрана (mss)
├── collect_and_label.py    # автосбор + АВТОРАЗМЕТКА из DOM (Playwright)
├── augment.py              # искусственное увеличение датасета (albumentations)
├── export_onnx.py          # best.pt -> best.onnx для автолейблинга в X-AnyLabeling
├── config.yaml             # конфиг кастомной модели для X-AnyLabeling
└── pyproject.toml          # зависимости (uv)
```

## Быстрый старт (Windows / Linux)

```bash
uv sync                      # поставить зависимости (ultralytics, mss, pyautogui, ...)
uv run train.py              # обучение (~10-20 мин на CPU)
uv run app.py                # запуск бота (окно игры должно быть на экране)
```

Опции бота: `uv run app.py --conf 0.4 --clicks 20 --buy-every 5`.
Остановка: Ctrl+C или увести мышь в левый верхний угол экрана.

## Как выполнялась работа

### Задача 1. Сбор данных
Игра открыта в Chrome, снято 36 скриншотов окна игры (1568×733) в разных
состояниях: разное число печенья, открытые/закрытые панели построек,
прокрученный магазин, с золотыми печеньками и без, с уведомлениями и без,
с включёнными и выключенными частицами. Папка `screenshots/`.

### Задача 2. Разметка
Разметка в формате YOLO HBB (`class cx cy w h`, нормировано 0..1).
Крестики уведомлений маленькие (~14×17 px), поэтому их боксы расширены на 8 px —
так детектор надёжнее их находит, а клик всё равно попадает в центр.
Данные разложены по `images/{train,val}` и `labels/{train,val}` (80/20),
имена картинки и txt совпадают.

### Задача 3. Обучение
`yolov8n.pt`, 60 эпох, `imgsz=800` (из-за мелких крестиков), CPU.
Аугментации под скриншоты: без отражений/поворотов и сдвига оттенка.
Главный артефакт — `runs/detect/clicker/weights/best.pt`.

### Задача 4. Интеграция
`app.py`: цикл «скриншот (mss) → детекция → действия (pyautogui)».
Приоритет: закрыть окно → забрать бонус → купить улучшение → кликать печеньку.
Покупается самое дорогое из доступных (нижнее в списке), не чаще раза в N секунд,
чтобы копить на следующие.

## Отчёт: модернизация проекта

1. **Автоматизация сбора данных** — `collect.py`: делает N скриншотов экрана
   с интервалом, пока пользователь играет. Полностью автоматический вариант —
   `collect_and_label.py`: игра запускается в управляемом браузере (Playwright),
   скрипт сам меняет состояние игры (печенье, покупки, золотые печеньки,
   уведомления) и снимает скриншоты.
2. **Автоматизация разметки** — два способа:
   * `collect_and_label.py` берёт координаты объектов прямо из DOM страницы
     (`getBoundingClientRect` для `#bigCookie`, `.shimmer`, `.product.enabled`,
     `.crate.upgrade.enabled`, `#notes .note .close`) и сразу пишет YOLO-разметку —
     ручная разметка не нужна вообще;
   * автолейблинг в X-AnyLabeling обученной моделью: `export_onnx.py` → `config.yaml`
     → Auto Labeling → Load Custom Model.
   Дополнительно `augment.py` увеличивает train-часть в k раз (яркость, шум,
   JPEG-сжатие, масштаб/сдвиг) с пересчётом боксов.
3. **Закрытие рекламы** — класс `close_ad` (крестики всплывающих окон), бот
   кликает по ним первым делом.
4. **Покупка улучшений** — класс `upgrade`: подсвеченные (доступные) здания в
   магазине и иконки улучшений; бот покупает самое дорогое доступное.
5. **Бонусы** — класс `bonus` (золотые печеньки), кликаются сразу при появлении.
6. `app.py` переписан под пункты 3–5 (см. выше).

Ответ на вопрос из методички: да, автолейблинг в X-AnyLabeling — это и есть
быстрый тест модели до написания кода: загружаем `best.onnx`, нажимаем
«разметить все» и глазами видим, где модель ошибается и на каких состояниях
игры не хватает данных.

## Запуск на Windows одним кликом

* `run_train.bat` — ставит uv (если нет), зависимости и обучает модель.
* `run_bot.bat` — запускает бота (`app.py`).
